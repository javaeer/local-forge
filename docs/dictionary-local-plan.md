# 离线词典 · 纯本地落地记录

> 定位：把「查词」从一次联网请求，变成一件**本地文件处理**。
> 数据源：CC-CEDICT（<https://cc-cedict.org>，CC BY-SA 4.0）。
> 不引入任何 npm 依赖，不新增 WASM，不发起任何跨域请求。

---

## 1. 结论先行

**已集成，路由 `/dictionary`，归入「文字 / 查阅」分组，首页第 48 张卡片。**

- 内核 `src/lib/dict.js`：解析 / 索引 / 检索三层，**纯函数、零 DOM**，`node --test` 可单测。
- 视图 `src/views/Dictionary.vue`：搜索、模式切换、结果展开、词库导入、来源声明。
- 数据 `public/dict/cc-cedict.txt.gz`：CC-CEDICT 快照，约 12 万条，gzip 后 ~3.8 MB。
  **不进 Git**（与 WASM 内核同一策略，避免 clone 膨胀）：`pnpm dev` / `pnpm build` 前由
  `fetch-dict --if-missing` 自动拉取，快照存在且校验通过即跳过。
- 更新 `pnpm dict:fetch`，校验 `pnpm dict:check`（CI 可当门禁）。

### 为什么值得做

搜索引擎里带「新华字典」字样的在线站，绝大多数**未获授权**——商务印书馆已公开声明《新华字典》无网页版，
并指出这些站点音形义错漏常见（如「倔强 jiàng」标成 qiáng）。它们的商业模式是引流做范文下载、起名测字，
不在释义质量上下功夫。LocalForge 的解法不是做一个「更准的在线字典」，而是：

> **把词库变成用户手里的文件**——一次取回、永久离线、可替换、可审计、查询词不出浏览器。

这恰好是本项目一贯的价值观（文件不上传、离线可用、源码可读），而非又一个「在线工具」。

## 2. 三层解耦

```
数据层  CC-CEDICT / Kaikki JSONL / TSV      ← 可替换，parseDict() 按扩展名+内容嗅探
  │
索引层  buildIndex(entries)                  ← Map(词→条目) + 排序数组 + 拼音/首字母倒排
  │
检索层  search(index, q, { mode })           ← 精确 / 前缀 / 拼音 / 首字母 / 释义 / 模糊
```

换数据源不改检索代码，换检索策略不碰解析器。这是刻意的：词典数据格式有十几种，
而「怎么查」的交互是产品决策，两者耦合会让任何一方都难以演进。

## 3. 几个非直觉的实现点

### 3.1 拼音标调不是「加个音标」

CC-CEDICT 存的是数字声调（`ni3 hao3`），直接显示很丑。`toneMark()` 按《汉语拼音方案》标调：

| 规则 | 例 |
| --- | --- |
| 有 a 标 a | `da4` → `dà` |
| 有 e 标 e | `xie4` → `xiè` |
| `ou` 标 o | `shou3` → `shǒu` |
| `iu` 标 u | `liu2` → `liú` |
| `ui` 标 i | `gui4` → `guì` |
| 轻声（5）不标 | `ma5` → `ma` |

`ü` 在 CC-CEDICT 里写作 `u:`（`nu:3`），输入侧统一折叠为 `v`——没有中文输入法的人敲 `lv4 se4`
也能查到「绿色」。这是「可输入性」优先于「教科书拼写」的取舍。

### 3.2 前缀检索用二分，不做全表 startsWith

12 万条 × 每次输入都跑 `startsWith` 会让输入框卡顿。索引阶段把词条按简体排序一次，
查询时 `lowerBound()` 二分定位，再线性收集同前缀项，命中上限即停。复杂度 O(log n + k)。

### 3.3 模糊匹配设两道闸

- **长度闸**：`|len(a) - len(b)| > maxDist` 直接跳过，省掉绝大多数无望比较。
- **行内早停**：Levenshtein 逐行动态规划，某一行最小值已超过阈值就返回，不再算完整矩阵。

模糊**不作为 `auto` 模式的默认路径**——它要遍历候选集，必须由用户显式选择，
否则每次敲键都多几十毫秒，交互体感会碎掉。

### 3.4 解压走原生，fflate 只做兜底

`DecompressionStream('gzip')` 是浏览器原生能力，零依赖、不占包体。仅在老浏览器或异常时
`await import('fflate')` 动态加载兜底——这样 99% 的用户不会为兼容性多下载一个解压库。

### 3.5 索引不落 IndexedDB

看似该缓存，实际不值得：

- 词库文件本身已被 Service Worker / HTTP 缓存住，二次加载不重新下载；
- 解析 + 建索引在 12 万条量级约 200–400 ms，配一个 loading 态即可；
- 一旦落库就要面对 schema 版本、词库替换后的脏索引、配额清理——**为一个查词工具背一套存储迁移，不划算**。

## 4. 体积与性能（实测，Node 22 / 桌面 Chrome）

| 阶段 | 数据 |
| --- | --- |
| CC-CEDICT 原始文本 | ~6.9 MB |
| gzip 快照 | ~3.8 MB |
| 解析 + 建索引 | 200–400 ms |
| 精确 / 前缀查询 | < 5 ms |
| 英文释义全文扫 | 100–300 ms（仅 `auto` 无命中或显式模式时触发） |
| 内存索引 | 约 40–60 MB（12 万条，按条目对象估算） |

> 体积取舍：词库是**静态资源**，不进 JS bundle，不参与 `check:bundle`（该门禁只管 JS/WASM 内核）。
> 对 InfinityFree 的 10 MB 单文件上限、Cloudflare Pages 的 25 MB 上限均安全。

## 5. 边界：它不替代什么

| 需求 | 本工具 | 应当使用 |
| --- | --- | --- |
| 日常查字、汉英互译、拼音反查 | ✅ | —— |
| 断网 / 隐私敏感场景查词 | ✅ | —— |
| 《现代汉语词典》第 7 版的规范释义 | ❌ | 商务印书馆官方 App（98 元买断） |
| 词源、历史语义演变（学术级） | ❌ | OED（图书馆读者卡可免费登录） |
| 国家标准科技名词 | ❌ | 术语在线 termonline.cn（官方免费） |

CC-CEDICT 是**社区维护**的词典，覆盖广、更新快，但不是国家语委的规范文本。
把它当作「可审计、可离线、可替换」的工程方案，而不是权威辞书的替代品——这条边界写在 UI 里，
避免用户误用。

## 7. 后续可做（未实现，避免过度设计）

1. **部首 / 笔画检索**：CC-CEDICT 不含部首字段，需引入 Unihan 数据（`kRSUnicode`），是独立数据源。
2. **词频排序**：当前按命中权重 + 词长排序，缺乏真实词频；可接 SUBTLEX-CH 语料提升常用词优先级。
3. **StarDict 二进制解析**：`.ifo/.idx/.dict` 格式解析工作量大于收益（CC-CEDICT 已覆盖主场景）。
4. **多词库并存**：当前导入即替换，改为「多源叠加 + 按源过滤」需要索引带 sourceId，留待真实需求出现。
