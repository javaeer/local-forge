本目录的韵书数据（rhyme.json.gz）由 scripts/fetch-classics.mjs 从上游拉取并转码生成，
**不随仓库分发**（.gitignore 已排除 *.gz）。首次使用请运行：

    npm run classics:fetch        # 或 npm run classics:check 仅校验现有快照

------------------------------------------------------------------
上游数据来源
------------------------------------------------------------------
项目：chinese_word_rhyme
地址：https://github.com/charlesix59/chinese_word_rhyme
许可：MIT

本次使用其中两份：
  - Pingshui_Rhyme.json   平水韵字表（5 声部 / 106 韵部 / 约 1.07 万字）
  - Word_Tune.json        平仄字表（约 8232 字，值域 平 / 仄 / 多）

上游 README 注明其数据出处为维基文库《平水韻》《詞林正韻》与维基词典，
属公共领域 / CC BY-SA 内容。

------------------------------------------------------------------
本项目所做的加工（均可由脚本复现）
------------------------------------------------------------------
1. 结构转码
   上游为 { "东": ["东","同",...] } 与 { "东": "平" } 形式，汉字被引号逗号淹没。
   这里转成紧凑字串（一韵一串、平仄三类各一串），未压缩体积约降至 1/6。

2. 补录「三讲」韵
   上游上声部自「二肿」直接跳到「四纸」，缺「三讲」整韵，致 106 → 105。
   连带后果是「讲/港/棒/蚌/项」等常用字在韵书与平仄表里双双缺失。
   补录字表据维基词典《平水韵·三讲》、搜韵、诗词会三源一致，均为仄声。
   上游若日后自行补齐，脚本会跳过补录、以 upstream 为准。

3. 由声部推导平仄
   上游平仄表仅覆盖韵书 77% 的字（8232 / 10671）。为免用户输入时满屏「未知」，
   改为以韵书声部推导为主（上平/下平为平，上/去/入为仄），再用平仄表补正，
   并把平仄两收的字标为「多」。实测 887 个两收字全部正确识别。

------------------------------------------------------------------
校验
------------------------------------------------------------------
scripts/fetch-classics.mjs 在生成与 --check 时都会断言：
  - JSON 可完整解析（下载被截断会在此拦下）
  - 韵部数 ≥ 100、韵书字数 ≥ 9000、平仄表字数 ≥ 7000
  - 平仄取值只允许 平 / 仄 / 多
  - 转码 pack → unpack 后与原结构逐字等价

生成的 rhyme.json.gz 约 33 KB，含 5 声部 / 106 韵部 / 10688 字 / 平仄表 8246 字。
